# 底层计算引擎编写

将数学定义直接表达为可调用的计算器。函数假定输入满足约定；输入准备与边界检查由调用层按实际需要完成。

## 回复与交付方式

- 直接在回复中提供可复制的 Python 代码，再解释公式对应关系、关键计算步骤、输入字段与返回结果。
- 计算器代码按放入 `.py` 的形式组织；需要调用示例时，另给适合 `.ipynb` 单元格的代码。只提供本次请求需要的部分。
- 不创建、修改或保存代码文件、notebook 或其他交付文件，也不自动应用补丁。可以只读查看已有文件以理解上下文。
- 验证示例直接放在回复中；只有能保证不写文件且不产生其他副作用时才可运行内存中的数值核对。未执行的示例明确说明未运行。

## 实现流程

1. 阅读当前公式、已有计算器和调用 notebook，确认字段含义、单位、时间顺序、计算参数及输出形状。遵循下述通用接口风格，不因已有示例绑定某个业务字段就照搬这种绑定。只有缺失信息影响数学结果时才向用户澄清。
2. 编写供 `.py` 使用的计算函数代码。数据输入使用 pandas DataFrame；置信度、窗口长度等允许作为独立参数。逐行计算先复制输入，在副本增加结果列并返回 DataFrame；汇总计算可返回标量或 Series。函数不修改调用方对象。
3. 按需提供供 `.ipynb` 使用的调用代码：读取或构造 DataFrame，准备字段与参数，导入计算函数，串联调用并展示结果。公式逻辑集中在计算器中；调用示例可保留独立的手算或期望值用于核对。
4. 提供教材例题、可核对的手算值或适用的数学关系用于验证。需要数值比较时采用适合公式精度的容差；简单断言按需要使用，不默认创建测试框架。遵守回复与交付方式中的运行限制，如实说明已核对与未运行的部分。

## 通用接口风格

- 围绕数学运算需要的数据角色设计接口，让同一计算可用于不同业务字段。列名、窗口、置信度等随调用场景变化的信息通过明确参数传入，具体业务映射由调用方决定。
- 参数命名表达计算角色；同一角色在同类函数中保持一致。`target_column` 只是单列输入的一个例子，不是强制名称。多个输入承担不同数学角色时，保留能区分这些角色的名字。
- 函数名表达计算方法或数学含义；若只是输入列或业务称谓不同而计算完全相同，复用一个函数，不按 P&L、收益率等标签重复实现。
- 不把当前示例的业务列名、头寸或常数固化为通用接口的默认值。没有自然通用默认值的参数由调用方显式提供；合理的数学参数默认值可以保留。
- 通用接口仍须明确输入的数学含义、单位、分布假设和输出口径。例如正态分位数计算可用于不同量纲的数据，而指数转换要求输入具有对应的对数含义；通过简短说明表达这些前提，不用业务专名或运行时校验替代。
- 采用满足当前复用需要的简单函数和显式参数。通用性不要求增加模式开关、自动猜测数据类型、兼容分支、类体系或配置框架。

## 计算层职责

- 输入约定用简短注释或 docstring 说明，涵盖必要字段、单位、顺序假设和公式口径；不转化为运行时校验框架。
- 假定字段、类型、单位、排序及数据有效性已满足要求。缺列检查、自动类型转换、清洗、补值、自动排序和异常兜底属于调用层，不加入底层计算器。
- 完整实现数学定义要求的分段和算法步骤。区分公式本身的定义域处理与无效输入保护：前者属于计算，后者由调用方负责。
- 保留运算自然产生的缺值，如 `shift(1)` 的首行 `NaN`；不默认填零、删除或替换成看似有效的结果。
- 采用直接的 pandas / NumPy 运算表达公式，保留算法实际需要的循环或分支。按当前计算需要设计函数，不额外构造服务层、配置框架或通用兼容层。
- 底层函数只计算并返回结果。文件访问、网络请求、展示、日志及数据准备留在调用层；随机模拟需要的随机性应通过明确参数或生成器控制。
- 年化天数、复利口径、收益定义等依照教材及任务约定；不将某个例子的常数推广为所有计算器的默认规则。
